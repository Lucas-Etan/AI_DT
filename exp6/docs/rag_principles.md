# RAG 实现说明

## 基本流程

检索增强生成的处理顺序是：读取文档并保留来源元数据，先按段落分组，再对过长段落按字符窗口切分且保留重叠；随后用文本嵌入模型把片段和问题映射为向量，将向量归一化后通过点积得到余弦相似度，选择 Top-K 片段，拼装带来源编号的上下文，最后交给生成器回答。每个片段应保存来源文件、片段编号、段落序号和字符起止位置，使回答能够反查原文。重叠窗口让位于切分边界的语句同时出现在相邻片段中，代价是索引略有重复；因此重叠长度必须小于窗口长度。回答完成后还要校验引用编号；如果最高相似度低于阈值，应拒绝回答，而不是让生成器猜测。检索、门控、生成和引用后处理应拆成独立模块，才能逐层定位错误，并让抽取式基线、在线 API 与本地模型复用完全相同的知识上下文。

## 嵌入与检索参数

本实验使用 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`。它可以在本地 CPU 上把中文或英文句段编码成三百八十四维稠密向量。实验调用 `encode` 时启用 `normalize_embeddings=True`，因此每个向量的二范数接近一；归一化向量的矩阵点积等价于余弦相似度。默认批量大小为十六，片段字符上限为二百六十，重叠长度为六十，问答默认取前三个片段。

## 错误分层

如果正确来源没有进入 Top-K，问题位于文档读取、切分、嵌入或检索阶段，称为检索错误。如果正确来源已经进入上下文，但回答遗漏事实、引用错误或越过资料编造，则属于生成或后处理错误。如果资料外问题被阈值挡住，是预期拒答；如果资料内问题因阈值过高而被挡住，则属于门控错误。排错时必须先检查检索列表，再检查生成文本。
