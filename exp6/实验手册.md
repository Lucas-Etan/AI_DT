# 实验 06　文本嵌入与 RAG 知识库问答

* **文本嵌入（text embedding）**：把一段文字转换成一串数值，使含义相近的文字在数值空间中也更接近。
* **RAG（检索增强生成）**：先从指定资料中检索证据，再让模型依据证据回答；它把“找资料”和“组织语言”分成两个步骤。

> 课程：人工智能开发技术（Python）  
> 对象：计算机科学与技术专业本科生  
> 学时：4 课时<br>
> 运行基线：Windows、Python 3.12、CPU、约 16 GB 内存

## 1. 实验内容与目的

### 先看看它能解决什么问题

当答案藏在一批本地资料里时，直接让大模型凭记忆回答容易遗漏依据。RAG 会先查找与问题相关的原文，再根据证据组织答案。下面先看几个具体场景，第一行是本实验实际完成的任务。

| 实际场景 | 输入什么 | 系统做什么 | 最终得到什么 |
|---|---|---|---|
| 本实验：课程资料问答 | 一个课程问题和 4 份本地课程资料 | 切分文档、检索相关片段、判断证据是否足够，再生成或抽取答案 | 带来源编号的回答；资料中没有依据时明确拒答 |
| 规章制度查询 | 学校或单位的制度文档与自然语言问题 | 从多份制度中定位相关条款 | 带原文出处的办理条件、流程或注意事项 |
| 产品手册故障排查 | 产品说明书、维护手册和故障描述 | 检索最相关的操作步骤与限制 | 可核对来源的排查建议，而不是脱离手册猜测 |
| 项目或论文资料检索 | 项目文档、研究笔记、论文摘要和查询 | 用文本嵌入找出语义相近的片段 | 相关资料列表和基于这些片段整理的回答 |

* **文档切分（chunking）**：把长文档拆成较短片段，便于分别计算嵌入和定位引用来源。
* **检索（retrieval）**：根据问题为资料片段计算相关分数，并返回最相关的一组片段。

这些应用都遵循“先检索证据，再决定是否回答，最后给出引用”的链路。本实验会把检索、门控、生成和评价拆开，让同学们能够判断错误究竟发生在哪个环节。

* **门控（gating）**：在调用生成器之前根据检索分数判断证据是否足够；不够时直接拒答，避免模型脱离资料猜测。

### 1.1 实验内容

本实验从已经准备好的实验骨架出发，带你完成一个可审计的小型 RAG 系统：

1. 读取 4 份本地课程资料，按段落和重叠窗口切成片段；
2. 用小型多语言文本嵌入模型在 CPU 上生成单位向量；
3. 用向量点积完成 Top-K 检索，并保存索引产物；
4. 建立“检索—门控—生成—引用后处理”链路；
5. 比较确定式抽取基线、本地 Qwen 小模型和在线 API 三种生成方式；
6. 用检索指标、拒答准确率和引用完整率定位系统错误。

* **重叠窗口（overlapping window）**：切分相邻片段时保留一部分重复文字，减少一句话刚好被边界截断而无法检索的问题。
* **单位向量（unit vector）**：长度被缩放为 1 的向量，使比较更关注方向，也就是文本含义，而不是数值整体大小。
* **向量点积与余弦相似度**：两个单位向量做点积后，结果就等于它们的余弦相似度；值越大，通常表示两段文字越相关。
* **Top-K 检索**：按相关分数从高到低返回前 K 个片段，K 表示保留的片段数量。
* **引用后处理**：生成回答后检查引用编号是否有效，并把编号映射回真实来源，防止出现不存在的引用。
* **确定式抽取基线**：不用大模型生成，而是按固定规则从检索片段中抽取答案；相同输入总会得到相同结果，可作为比较基准。

## 2. 问题拆解与技术路线

| 层次 | 输入 | 输出 | 检查点 |
|---|---|---|---|
| 资料层 | Markdown/文本 | 带来源和偏移的片段 | 数量、边界、重叠 |
| 检索层 | 片段与问题 | Top-K 命中 | 来源、分数、Hit@K |
| 生成层 | 问题与编号上下文 | 带引用的草稿 | 是否只依据上下文 |
| 应用层 | 草稿与命中 | 最终回答或拒答 | 阈值、引用映射、错误归因 |

* **Hit@K**：只检查正确片段是否至少有一个出现在前 K 个检索结果中，不关心一共命中了多少个正确片段。

\[
q\xrightarrow{E}\hat q,\qquad d_i\xrightarrow{E}\hat d_i,\qquad
s_i=\hat d_i^\mathsf{T}\hat q
\]

嵌入做 L2 归一化后，单位向量点积等于余弦相似度。系统按分数降序取 Top-K；最高分低于阈值时直接拒答，不调用生成器。

## 5. 阶段一：资料读取与切分

### FILL-01：按稳定顺序读取资料

RAG 的第一步是把资料变成稳定、可追踪的文档列表。下面只接收 `.md` 和 `.txt`，按路径排序后以 UTF-8 读取，跳过空文件，并在整个知识库为空时立即失败；这样后续片段编号不会随文件系统顺序漂移。

~~~python
paths = sorted([*docs_dir.glob("*.md"), *docs_dir.glob("*.txt")])
documents = []
for path in paths:
    text = path.read_text(encoding="utf-8").strip()
    if text:
        documents.append((path, text))
if not documents:
    raise ValueError(f"知识库为空：{docs_dir}")
return documents
~~~

关键解释：排序保证索引编号稳定；空文档不能进入嵌入模型；异常应尽早暴露，而不是得到一个看似成功的空索引。

### FILL-02：段落优先、长段滑窗

**理论说明：** 整篇文档通常长于嵌入模型适合检索的语义单元，但简单定长切断又可能把一个事实截在边界两侧。这里采用“段落优先、长段滑窗”：先校验 `0 <= overlap < size`，一级标题只作元数据，二级标题与正文合并；下面的窗口逻辑让相邻长片段保留 60 个字符重叠。

~~~python
starts = range(0, len(paragraph), size - overlap)
for window_no, start in enumerate(starts, start=1):
    piece = paragraph[start:start + size].strip()
    if not piece:
        continue
    end = min(start + size, len(paragraph))
    chunk_id = f"{path.stem}-p{paragraph_no:02d}-w{window_no:02d}"
    chunks.append(Chunk(chunk_id=chunk_id, source=path.name,
        title=title, paragraph=paragraph_no,
        char_start=start, char_end=end, text=piece))
    if start + size >= len(paragraph):
        break
~~~

在此片段前还需：用正则 r"\n\s*\n" 分段；暂存单独出现的二级标题；用 enumerate(paragraphs, start=1) 产生 paragraph_no。步长必须是 size-overlap。

### FILL-03：合并各文档片段

读取和单文档切分已经分别完成，下面只负责遍历所有文档并汇总片段。它连接两个可独立测试的函数，不在此重复解析规则。

~~~python
chunks: list[Chunk] = []
for path, text in read_documents(docs_dir):
    chunks.extend(split_document(path, text, size, overlap))
return chunks
~~~

关键解释：此处只负责编排，不重复实现读取或切分，使三个函数可以分别检查。

## 6. 阶段二：CPU 文本嵌入

### FILL-04：明确在 CPU 上加载模型

文本片段需要转换为可比较的向量。下面在构造嵌入器时保存批大小，并明确把 Sentence Transformer 加载到 CPU；这是后续批量编码的准备步骤，也避免设备自动选择造成环境差异。

~~~python
self.batch_size = batch_size
self.model = SentenceTransformer(model_name, device="cpu")
~~~

关键解释：明确指定 CPU 可让不同设备上的结果更容易比较，本实验不依赖显卡。

### FILL-05：批量编码并归一化

**理论说明：** 检索阶段希望用一次矩阵点积比较查询与全部片段，因此每个向量都要先做 L2 归一化。下面拒绝空输入，按批编码文本，返回统一的 `float32` NumPy 矩阵；归一化后点积就等价于余弦相似度。

~~~python
if not texts:
    raise ValueError("待编码文本不能为空")
vectors = self.model.encode(
    texts, batch_size=self.batch_size,
    show_progress_bar=False, convert_to_numpy=True,
    normalize_embeddings=True,
)
return np.asarray(vectors, dtype=np.float32)
~~~

关键解释：归一化使每行范数约为 1；float32 足以完成本实验，并比 float64 节省一半矩阵内存。

**实践方式：** 将 FILL-04 和 FILL-05 放入 `embedding.py`。下面用两条短文本作为测试用例，真实调用嵌入模型并计算每行范数；首次执行可能下载模型。

## 7. 阶段三：索引与 Top-K 检索

### FILL-06：建立并持久化索引

检索器必须让向量第 i 行与第 i 个片段始终对应。下面一次性编码所有片段，同时保存向量矩阵和完整元数据，再用同一对内存对象构造 Retriever；它连接离线建索引与在线查询。

~~~python
output_dir.mkdir(parents=True, exist_ok=True)
vectors = embedder.encode([chunk.text for chunk in chunks])
np.save(output_dir / "embeddings.npy", vectors)
data = [chunk.model_dump() for chunk in chunks]
(output_dir / "chunks.json").write_text(
    json.dumps(data, ensure_ascii=False, indent=2),
    encoding="utf-8")
return cls(chunks, vectors, embedder)
~~~

关键解释：向量与片段必须保持相同行序；chunks.json 保留来源、段号和偏移，便于审计命中。

### FILL-07：点积排序并返回命中

**理论说明：** 查询到来时，只需把问题编码成同一空间中的单位向量，再与片段矩阵做点积并按分数降序取 Top-K。下面还处理空问题和越界 K；得到的分数只用于相对排序，不应解释成答案正确概率。

~~~python
if not question.strip():
    raise ValueError("问题不能为空")
k = min(max(1, top_k), len(self.chunks))
query = self.embedder.encode([question])[0]
scores = self.vectors @ query
order = np.argsort(-scores)[:k]
return [SearchHit(chunk=self.chunks[i],
                  score=float(scores[i])) for i in order]
~~~

关键解释：负分数让 argsort 按分数从高到低排列；K 被限制在有效范围。分数用于排序，不是正确概率。

**实践方式：** 将 FILL-06 和 FILL-07 放入 `retrieval.py`，运行下面的真实检索测试。它会建立索引，并询问一条能由课程概述回答的问题。


## 8. 阶段四：编号上下文与引用后处理

### FILL-08：把命中片段编号

检索结果要交给生成器阅读，同时还要让答案中的编号能反查原资料。下面按当前排名给每个片段编号，并携带来源、片段 ID、相似度和正文；它把内部 SearchHit 转成可审计的提示上下文。

~~~python
blocks = []
for number, hit in enumerate(hits, start=1):
    blocks.append(
        f"[{number}] source={hit.chunk.source}; "
        f"chunk={hit.chunk.chunk_id}; score={hit.score:.4f}\n"
        f"{hit.chunk.text}")
return "\n\n".join(blocks)
~~~

关键解释：回答中的 [1] 必须能反查第 1 个命中，而不是任意文献编号。

### FILL-09：删除越界引用并追加来源映射

**理论说明：** 生成器可能写出并不存在的 `[9]` 等编号，应用至少要阻止这种不可追踪引用进入最终答案。下面只保留当前命中范围内的编号，并在答案末尾追加编号到文件/片段的映射；这能验证引用存在，但不能自动证明句子受到来源支持。

~~~python
valid = {str(i) for i in range(1, len(hits) + 1)}
cleaned = re.sub(
    r"\[(\d+)\]",
    lambda m: m.group(0) if m.group(1) in valid else "",
    raw,
)
sources = [f"[{i}] {h.chunk.source}#{h.chunk.chunk_id}"
           for i, h in enumerate(hits, start=1)]
return cleaned.strip() + "\n\n来源：\n" + "\n".join(sources), sources
~~~

关键解释：后处理只能删除不存在的编号，不能证明句子事实正确。

**实践方式：** 将 FILL-08 和 FILL-09 放入 `context.py`。下面先构造两个真实命中，再故意提供一个合法 `[1]` 和一个越界 `[9]` 作为后处理测试。

~~~powershell
.\.venv\Scripts\python.exe -c "from app import build_retriever; from context import build_context,finalize_answer; h=build_retriever().search('提交包必须包含什么？',2); print(build_context(h).splitlines()[0]); print(finalize_answer('依据资料回答[1]，伪引用[9]。',h)[0])"
~~~

**运行验证：** 第一行应以 `[1] source=` 开始；最终文本保留 `[1]`、删除 `[9]`，并列出两个可追踪来源。

**QA：** 若 `[9]` 仍存在，检查正则替换是否使用 `valid` 集合；若合法编号也消失，确认集合元素和正则捕获值都是字符串；若来源编号与上下文顺序不同，两个函数必须都从 1 开始遍历同一份 `hits`。

## 9. 阶段五：三种生成器

### FILL-10：确定式抽取基线

在引入生成模型前，需要一个完全离线、可复核的最低基线。下面从前两个命中各取第一个完整句并附上对应编号；它不改写事实，语言不够自然，但能帮助区分“检索问题”和“生成问题”。

~~~python
sentences = []
for i, hit in enumerate(hits[:2], start=1):
    first = re.split(
        r"(?<=[。！？])", hit.chunk.text, maxsplit=1
    )[0].strip()
    sentences.append(f"{first} [{i}]")
return "抽取式基线（非大语言模型）：\n" + "\n".join(sentences)
~~~

关键解释：确定式基线可离线运行，输出不够自然但易于复核，适合作为最低可用方案。

### FILL-11：在线 API 生成器

在线生成器使用相同上下文，但凭据和服务地址只能来自环境变量。下面只在三项配置齐全后创建有超时、有限重试的客户端，并用低温度请求回答；它是可选生成后端，不影响本地必做路径。

~~~python
client = OpenAI(api_key=key, base_url=base_url,
                timeout=90.0, max_retries=2)
response = client.chat.completions.create(
    model=model,
    messages=[{"role": "system", "content": SYSTEM_PROMPT},
              {"role": "user",
               "content": f"上下文：\n{context}\n\n问题：{question}"}],
    temperature=0, max_tokens=300,
)
return (response.choices[0].message.content or "").strip()
~~~

关键解释：密钥只从环境变量读取；低温度提高可重复性；超时和重试必须有上限。不要把密钥写进源码、截图或报告。

### FILL-12：本地 Qwen 确定性生成

本地生成器让你在无 API 的情况下也能观察小模型输出。构造函数已经在 CPU 上加载 Qwen2.5-0.5B-Instruct；下面对模板化提示执行确定性生成，只解码输入之后的新 token，避免把检索上下文重复到答案中。

~~~python
inputs = self.tokenizer(prompt, return_tensors="pt")
with torch.inference_mode():
    output = self.model.generate(
        **inputs, max_new_tokens=180, do_sample=False,
        repetition_penalty=1.05,
        pad_token_id=self.tokenizer.eos_token_id,
    )
new_tokens = output[0, inputs["input_ids"].shape[1]:]
return self.tokenizer.decode(
    new_tokens, skip_special_tokens=True).strip()
~~~

prompt 应由 apply_chat_template 产生，并设置 tokenize=False 和 add_generation_prompt=True。只解码输入长度之后的新 token；inference_mode 关闭梯度；do_sample=False 便于比较。

本阶段暂不单独运行：三个生成器需要下一阶段的门控与上下文连接后再分别检查。

## 10. 阶段六：连接 RAG 管线

### FILL-13：检索、前置门控、生成与后处理

**理论说明：** RAG 不只是“检索后调用模型”，还必须决定什么时候不该生成。下面按“检索 → 相似度门控 → 构造上下文 → 选择生成器 → 引用后处理”连接各模块；资料外问题在生成器之前返回，从源头避免无依据回答和不必要的 API/CPU 消耗。

~~~python
hits = retriever.search(question, top_k)
top_score = hits[0].score if hits else 0.0
if not hits or top_score < threshold:
    return RagResult(question=question, mode=mode,
        answer=REFUSAL_TEXT, refused=True,
        top_score=top_score, sources=[], hits=hits)
context = build_context(hits)
raw = get_generator(mode).generate(question, context, hits)
answer, sources = finalize_answer(raw, hits)
return RagResult(question=question, mode=mode, answer=answer,
    refused=False, top_score=top_score, sources=sources, hits=hits)
~~~

关键解释：资料外问题在调用生成器前返回，可避免 API 费用和本地算力浪费。阈值 0.34 只对本实验语料和样本有效。

## 11. 阶段七：检索与端到端评价

### FILL-14：计算 Hit@K 与 Recall@K

检索评价只针对有正确来源集合的 8 个资料内问题。下面比较实际命中来源 `got` 与标准来源 `gold`：Hit@K 关心是否至少命中一个，Recall@K 关心应找来源的覆盖比例，并保留逐题记录供诊断。

~~~python
hit = float(bool(got & gold))
recall = len(got & gold) / len(gold)
hit_sum += hit
recall_sum += recall
rows.append({"question": case["q"],
             "retrieved": sorted(got),
             "hit": hit, "recall": recall})
~~~

循环结束后返回 K、两个均值和逐题记录。Hit@K 只问是否至少命中一个正确来源；Recall@K 还关心多个来源是否找全。

### FILL-15：评价拒答、引用并进行归因

**理论说明：** 端到端失败要落到具体层次，而不是只给一个总分。下面依次判断检索错误、门控错误、生成/后处理错误和通过；资料外样本同时用于评价拒答，非拒答样本还检查每个来源编号是否实际出现在答案中。

~~~python
if case["scope"] and not (got & set(case["gold"])):
    diagnosis = "RETRIEVAL_ERROR"
elif case["scope"] and result.refused:
    diagnosis = "GATING_ERROR"
elif not result.refused and not valid_markers:
    diagnosis = "GENERATION_OR_POSTPROCESS_ERROR"
else:
    diagnosis = "PASS"
~~~

返回 refusal_accuracy、citation_completeness 和逐题 rows。引用标记齐全只证明可追踪，不证明引用支持答案。

~~~text
K=3: Hit@K=1.000, Recall@K=1.000
~~~

**QA：** 数值不同时先检查片段数量、归一化、排序方向、阈值和指标分母；Hit@K 正常而 Recall@K 偏低时，查看多来源题是否漏召回；引用完整率低时检查后处理编号映射；不要通过改标准答案或只删除失败样本来抬高指标。

## 14. 常见问题与排查（QA）

### Q1：py -3.12 找不到解释器怎么办？

安装 Python 3.12，并确认启用了 Python Launcher。重新打开 PowerShell 后执行 py -0p 查看版本。

### Q2：为什么始终使用 .venv\Scripts\python.exe？

它明确绑定本实验环境，避免误用系统 Python 或其他课程环境。

### Q3：依赖安装很慢或中断怎么办？

先确认网络，再执行原安装命令。不要删除已有下载缓存。

### Q4：模型下载后磁盘占用增加是否正常？

正常。嵌入模型约 0.45 GiB，本地 Qwen 约 0.93 GiB；提交时不要复制缓存。

### Q5：为什么片段数不是 13？

检查标题是否被当成独立片段、空段是否过滤、长段停止条件和步长是否正确。

### Q6：overlap 大于或等于 size 会怎样？

步长为零或负数，算法失效。函数应在开始处抛出 ValueError。

### Q7：中文文件读取乱码怎么办？

确认资料未被改写，并明确使用 UTF-8，不依赖系统默认编码。

### Q8：为什么向量使用 float32？

它满足当前检索精度并节省内存，同时固定类型便于比较。

### Q9：向量范数不是严格 1.0 是错误吗？

不是。浮点计算有微小误差；例如 0.99999994 属于正常结果。

### Q10：首个命中来源不正确，应先改提示词吗？

不应。先检查资料、切分、嵌入、排序和问题文本；提示词属于后面的生成层。

### Q11：分数 0.67 是否表示 67% 正确率？

不是。它是当前嵌入空间中的相似度，不是概率。

### Q12：资料外问题没有拒答怎么办？

检查 top_score 是否在生成器调用之前与阈值比较，并确认阈值未被改动。

### Q13：回答中出现越界编号怎么办？

检查后处理正则和有效编号集合；还要人工确认保留下来的引用是否支持句子。

### Q14：本地 Qwen 很慢或内存紧张怎么办？

先完成抽取基线；关闭大内存程序，保持 180 个新 token 上限并确认模型为 0.5B。

### Q15：本地模型回答被截断怎么办？

记录为模型限制。资源允许时可小幅提高 token 上限，但需重新记录耗时与输出。

### Q16：在线模式出现 401 怎么办？

检查密钥有效性和首尾空格，不要打印密钥。

### Q17：在线模式出现 404 怎么办？

核对基础地址和模型名；有些兼容端点要求地址以 /v1 结尾。

### Q18：在线模式出现 429 或超时怎么办？

429 表示限流；等待后再试。超时可能来自网络或服务端，保留错误记录，不伪造输出。

### Q19：为什么资料外样本不计算 Recall@K？

资料外样本没有正确来源集合，适合评价拒答。

### Q20：评价值不同能否直接改阈值？

先排除实现错误。若确需校准，应记录候选阈值、分数分布和选择依据。
